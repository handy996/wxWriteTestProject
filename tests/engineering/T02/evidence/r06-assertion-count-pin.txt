after each command (`$LASTEXITCODE`), never inferred from the wrapper (a pwsh exit 0 with a failed

Composition, R05 -> R06 (real counts; nothing was deleted to reach the number):

- R05 shipped **139** controls assertions. The round-5 review's structural weakness was that a
  wildcarded config could take 139 down to 115 with every remaining line green: no assertion looked at
  the total, and void probes are excluded silently.
- R06 adds **+66** super-string controls (6 new adjacency shapes - `_`, dash-prefix, dash-suffix,
  dot-suffix, `=`-suffix, and dashes on both sides - over 11 values), **+2** AWS entropy/example
  corner controls, **+14** span controls, **+1** the pin = **222**, with 0 void probes.
- The `>= 40` mutation tolerance is now `mutation_total == 44` plus a per-value
  "all 4 single-character probes stay live" for each of the 11 values.
- Red control: a variant of the gate with the pinned total moved off the measured value makes the pin
  the ONLY failing assertion (see evidence/r06-red-control-variants-final.json).

The concurrency line (run 6) is not cosmetic: before it, two full-battery runs started in this working tree wiped each other's probe files through a shared fixed scratch path and produced two false reds. The delivered battery now keeps its probes under `allowlist-controls-<pid>`, and the regression test is two simultaneous runs that both come back `223 PASS / 0 FAIL / 0 NOTE`, exit 0.

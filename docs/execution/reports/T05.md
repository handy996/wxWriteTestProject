## 3. 四类资源的状态机、版本分配与不可变规则

### 3.1 状态机

| 资源 | 状态 | 转换 | 不可变规则 |
|---|---|---|---|
| `editorial_skill` | 身份（无状态） | 创建后 `activeVersionId` 仅指向 PUBLISHED 非 RETIRED 版本 | 乐观锁 `lock_version`；`code` 全局唯一 |
| `editorial_skill_version` | DRAFT → PUBLISHED → RETIRED | DRAFT 可编辑；PUBLISHED 不可覆盖（内容锁定）；RETIRE 仅改受控状态；RETIRED 终态 | 服务层 + DB 触发器 `t05_skill_version_guard`（SECURITY DEFINER）双重保证发布后 `config/rules_hash/version/schema_version/parent_version_id/change_log/skill_id` 不可变 |
| `policy_version` | DRAFT → PUBLISHED → RETIRED | 同上 | 触发器 `t05_policy_version_guard`；`rules/hash/version/policy_type` 发布后不可变 |
| `prompt_version` | DRAFT → PUBLISHED（无 RETIRED） | 发布模板不可变，修改必须新版本 | 触发器 `t05_prompt_version_guard`；`system_template/user_template/output_schema/hash` 发布后不可变 |

### 3.2 版本分配

- 新 Skill 无版本时 `baseVersionId` 必须为 null，服务端分配 `1.0.0`；已有版本时必须传同一 Skill 的 `baseVersionId`。
- 新版本号 = 该 Skill **全部 DRAFT/PUBLISHED/RETIRED 版本**的最大 semver 的 patch+1，永不重用（草稿/发布/退休都不允许回退或复用）。
- 并发防线：锁 Skill 身份行（`pg_advisory_xact_lock("T05_SKILL|"+skillId)`）+ `UNIQUE(skill_id, version)` 作为最终数据库防线。两个首版请求串行后仅第一条成功（第二条 `409 BASE_VERSION_REQUIRED`）。
- 复制其他 Skill 的版本返回 `422 CROSS_SKILL_BASE_VERSION`。

### 3.3 快照不可变

`SkillSnapshot` / `PolicySnapshot` 是**对特定版本行的投影**，从不读取可变“当前头”：发布新版本或退休旧版本只改该版本行，不影响历史版本行，因此历史任务继续读取原快照（原 ID/version/rulesHash/config/policySnapshots）。`SkillSnapshot.read` 仅对 PUBLISHED/RETIRED 返回，DRAFT/缺失返回 `SKILL_NOT_PUBLISHED`；`PolicySnapshot.read` 对缺失返回 `POLICY_NOT_FOUND`。

## 4. 校验方式

### 4.1 结构校验（冻结 editorial.schema.json）

`JsonSchema` 是使用既有 Jackson 的 JSON Schema 2020-12 **子集校验器**（无新增依赖，未改 pom.xml），支持当前冻结输入涉及的 `type/const/enum/format(uuid)/minLength/maxLength/minItems/maxItems/items/properties/required/additionalProperties/pattern/minimum/maximum/anyOf/$ref`，整改后不存在的 `$ref` 会明确拒绝。它不是完整的 JSON Schema 实现；先前“所有未支持关键字都会报错”的描述不准确，不应外推至任意 Schema。它直接加载 `resources/skills/editorial.schema.json`（与 `docs/schemas/editorial.schema.json` 字节一致），对 `$defs/SkillConfig` 及请求 DTO 做结构校验；四个 Prompt 的固定输出样例及负例也使用该冻结文档验证。

### 4.2 语义校验（服务端，`SkillConfigValidator`）

- `factPolicyRef` 必须引用存在的 `FACT` 类型 PUBLISHED 政策；`licensePolicyRef` 必须引用 `LICENSE` 类型 PUBLISHED 政策（否则 `POLICY_REF_INVALID`/`POLICY_NOT_FOUND`）。
- `promptBindings` 必须**恰好覆盖四个基线 Agent**（Analyzer/Writer/EditorialReviewer/WriterRevision，各自唯一），每个 `promptVersionId` 必须存在、agentName 匹配、状态 PUBLISHED、且 `hash` 与服务端重算的 Prompt hash 一致（否则 `PROMPT_BINDING_INVALID`/`PROMPT_HASH_MISMATCH`）。
- `outputSchema` 名称必须存在于冻结 `$defs` 且与所绑定 Prompt 的 `$ref` 一致，否则 `PROMPT_OUTPUT_SCHEMA_INVALID`；创建、编辑、发布共用此校验。四个 Agent 分别绑定 `AnalysisOutput`、`WriterOutput`、`ReviewOutput`、`RevisionOutput`。
- 内置基准用例：`readabilityRules` 必须满足 `recommendedMin ≤ recommendedMax`、`longParagraphWarning < veryLongParagraph`、`shortParagraphMax < recommendedMin`（否则 `READABILITY_INVARIANT_VIOLATION`）。

### 4.3 hash（全部服务端计算，客户端不可申报）

- **rulesHash** = `SHA-256(canonical-v1(SkillConfig))`，创建/编辑时计算，发布时重算并核对。
- **Policy hash** = `SHA-256(canonical-v1(rules))`。
- **Prompt hash** = `SHA-256(canonical-v1({systemTemplate, userTemplate, outputSchema}))`，覆盖规范化后的实际模板与 Schema。
- 全部复用 `CanonicalRequest.canonical` + `digest`（canonical-v1：键排序、无空白、UTF8、拒绝 float/surrogate/非 ASCII 键）。

## 5. 硬政策不可降低的实现与反例证据

硬政策（FACT/LICENSE/QA/WATERMARK/COST）以不可变 PUBLISHED 基线加载。Skill 只能收紧、不能放松：

- **结构上不可能关闭**：冻结 `SkillConfig` 为 `additionalProperties:false`，不含任何“关闭事实/版权/水印/成本/批准”字段；客户端传入 `skipFactCheck`/`status`/`rulesHash`/`publishedBy`/`actorId`/`ownerId` 等一律被结构校验拒绝（反例测试 `JsonSchemaSkillConfigTest.rejectsUnknownField/rejectsBadUuidAndClientDeclaredFields` 与 `T05PostgresTest.invalidConfigRejected`）。
- **语义上强制绑定**：`factPolicyRef`/`licensePolicyRef` 必填且必须是正确类型、PUBLISHED 状态的政策；不存在或类型错误即拒绝。
- **基准用例守卫**：readability 阈值乱序（如 `recommendedMin=999`）在创建即被拒（`READABILITY_INVARIANT_VIOLATION`）。
- `examples`/`antiExamples` 仅作为字符串数据存储与展示，永不进入 `systemTemplate`（`systemTemplate` 由四个不可变 Prompt 基线固定，数据经数据通道 `{{...}}` 传入，不拼接为系统指令）。
- `COST` 政策不绕过 T08/T09 预算预占与对账（T05 只登记规则，不在本任务实现预算）；`LICENSE` 政策不使 UNKNOWN/NC/ND/未满足 SA 自动可用；`QA/WATERMARK` 政策不使缺失检查/缺失水印变通过。这些规则内容见 `resources/skills/policies/*.json`。

### 输入与 AST

- `ArticleAst.decode(byte[])` 严格按 UTF-8 解码并检查实际 1 MiB 字节上限；粘贴/JSON 创建再次计算内容 UTF-8 字节，解析后按非空白 Unicode 码点检查 100–30,000。包含 emoji、非 BMP、NBSP、Unicode 空格；不截断。
- TXT/Markdown 文件接入：调用方严格解码原文件字节，将结果放入冻结 `original.content`，TXT 设 TEXT，Markdown 设 MARKDOWN，再调用既有 JSON POST。服务端再次检查容量和 Unicode。没有新增 multipart/上传路由；文件解码失败不得用 replacement character 转成另一份内容。当前没有负责文件选择的前端。
- 支持受限段落、ATX 标题、连续列表、引用和嵌套 bold/italic/HTTPS 行内链接。明确拒绝 HTML、非法 UTF-8/surrogate/NUL、远程图片语法、引用式链接、代码块/内联代码、表格等未支持语法；不抓取任何远程内容。它不是完整 CommonMark 实现。
- AST 严格字段/类型/范围校验；list.text 与 items 一致；其他块 items 为空；heading level 与 placeholder slotId 互斥规则、marks、claimRefs 和 slot 引用均有受控校验入口。placeholder 只在内部 AST 编辑接口表示编辑标记，不创建 T19 Slot。
- 原稿分配随机稳定 sectionId/blockId，保存后读取和重放不重新分配；同 section 的块共享 sectionId，blockId 全版本唯一，保留 `title/subtitle` 锚点名称。克隆重新映射 section/block，清空 Claim 引用并移除旧 Slot 标记。
- plainText 从 AST 块 text 按换行连接派生；title/subtitle 单独保留。Span 为码点半开区间，校验真实块文本、quote、blockHash；`validateSpan(actor,article,version,span)` 先验证 Owner/同文章版本，支持标题、副标题锚点。
- SHA-256 与 canonical-v1 复用 T03，不复制公共组件。contentHash 仅覆盖 schemaVersion/title/subtitle/contentAst，blockHash 是实际文本 UTF-8。冻结 expected hash 未修改。**emoji/control escaping 修复仅随共享补丁交主 agent，测试副本已应用；当前共享源码本身仍需该修复。**

### 创建、存储和数据库

先用 T03 幂等事务探测重放/冲突；只有新创建才退出事务、分配原稿并进行 T04 stage，然后重新进入 T03 幂等事务，重新鉴权/加锁/重放检查。避免所有连接被并发事务占满、T04 独立暂存审计拿不到连接。并发输家最多留下可回收暂存对象，不生成第二份业务记录。

同一成功事务写 Job（指针暂空）、Original、RightsSnapshot 历史、Skill/Prompt/Policy 快照、对象引用、业务审计、回填指针、幂等结果。ObjectRef hash 是所存完整版本 JSON 的物理 hash；内容 hash 是契约内容投影 hash，两者明确区分，通过 `VERSION_OBJECT` Ownership 适配与 T04 校验实际字节。提交后的 completion 标记沿用 T04 协议。

迁移包含同文章复合 FK、唯一版本号/单个 Original、提交时完整性 constraint trigger、Original 指针不可改、版本 ancestry 限制、RightsSnapshot 归属/历史追加保护、CANCELLED 与 deletion_pending 写入守卫。运行账号对版本仅 SELECT/INSERT，不能 UPDATE/DELETE；Job 有乐观锁和受控写入口。审计/幂等/对象引用失败使业务事务回滚；暂存审计是 T04 的独立最小元数据记录，不代表文章创建成功。

金额以定标字符串校验、BigDecimal/numeric(18,6) 保存，USD；不执行预占、扣费或结算。预算仅支持维持或增加，降低返回明确冲突，避免越过 T08 未接入的资金守卫。

### 删除与恢复交接

`DeletionHandoff` 是无需领域新表的 ADR-006 协作协议：T10 Commands 在短事务鉴权→重放→ETag/预览/hold 守卫→持久命令与 fencing；返回后 T04/T37 Journal 追加 REQUESTED；T10 持久化回执后才返回 202。明确检查外部 journal 时没有活动 DB 事务。预览缺完整领域统计返回 503；过期 409、旧锁 412；未知保留政策/hold 拒绝。Journal 故障统一 503 DELETION_JOURNAL_UNAVAILABLE；登记成功但本地回执失败不会返回成功，重试复用同 deletionId。

默认生产装配并未安装这些 durable adapters。真实预览统计、保留策略、签名/独立恢复域、删除命令持久化、PURGE_COMPLETED 后 operation 成功、恢复屏障和晚到结果清理属于 T10/T04/T37 集成。协议测试是具名内存替身，不证明真实 journal、真实幂等命令、S3 或删除灾备。

## 4. 最小共享变更申请与迁移/恢复风险

[shared-integration.patch](../../../tests/engineering/T06/shared-integration.patch) 可由主 agent 审阅，包含：

1. **CR-T06-01：JSON envelope 上限。** T03 `CanonicalRequest.parse` 原 1 MiB 是整个请求的限制，错误地排除合法 1 MiB 原文及 JSON 转义。申请扩大公共 canonical 解析安全上限至 8 MiB；各路由仍保留自己的 HTTP body/实际内容容量限制，T06 原文仍严格 1 MiB。本次 HTTP 精确边界已验证。
2. **CR-T06-02：canonical-v1 UTF-8/控制字符。** 使用当前 Jackson 提供的 COMBINE_UNICODE_SURROGATES_IN_UTF8，并关闭 WRITE_HEX_UPPER_CASE，保证非 BMP 原样 UTF-8、JSON 控制字符小写十六进制。冻结正文 expected `1eb8eef…0860`，旧实现实际 `32c21c…3c50`；不能改 frozen hash 来适配旧实现。未批准上线前必须由 T03/主 agent 处理。**如有旧实现生成的非 BMP/控制字符历史数据，不得原地改写不可变版本/hash；须盘点并安排受控兼容/新版本方案，旧幂等请求 hash 也有兼容风险。当前没有已批准 T03 正式发布基线，本次升级测试不能证明该历史兼容性。**
3. **CR-T06-03：composition root。** 提交 `ArticleIntegration.java` 接线源码及新增文件 patch，将跨域适配限制在 bootstrap；article 生产目录只编译依赖 shared。需要主 agent 启用 `editorial.article.enabled=true`、`editorial.storage.enabled=true`、T03 已批准身份接线及可靠 cursor-key/Local/S3 配置。没有覆盖损坏的 T03 旧 patch；runner 的等价接线完整可读。
4. **契约/依赖待闭合：** 冻结 ports 只有具名业务协议，没有可直接复用的 Java Changes、Evidence、durable deletion SPI。本次是 consumer-owned 小接口，待 G2 由主 agent 决定是否提升到 shared。CloneRequest 缺少新稿依据字段，以 UNKNOWN 保守交付，不扩充路由/DTO。生成输入变化后的真实 workflow 引用、其他领域 ArtifactRef 聚合、费用账本联动、全量删除统计均需各拥有者接入。

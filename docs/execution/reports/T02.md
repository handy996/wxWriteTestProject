## 审核整改 R02c（2026-10-08）：Gitleaks 例外只按值，指纹清单分行记录

第三方复审判决 R02 未闭合（`docs/execution/reviews/T02-round3/review.md` F-01/F-02/F-03）。本轮只改 T02 自有文件，逐条撤回上文被证伪的表述；完整命令、退出码与四控制实测数字见 [T02-Revision-R02.md](T02-Revision-R02.md)。

**Gitleaks 8.30.1 的 `[[allowlists]]` 中 `paths`（文件条件）语义。** 命中判定分两步：先用规则正则读文件，再用 allowlist 决定抑制。`paths` 与 `regexes` 同时出现且 `condition = "AND"` 时，实测行为是**路径命中的文件整体不进入扫描**，值条件形同虚设：扫描日志自报 `scanned ~0 bytes (0)`，向该文件追加合成 GitHub PAT 与 PEM 私钥块后仍为 0 命中；把同一 allowlist 的 `paths` 行删除、只留 `regexes`，则同一文件报 `scanned ~150,604 bytes`，被豁免的那个值仍不报、植入的凭证全部被抓。结论：`paths` 是整文件豁免，不是「值在该文件时才豁免」。复现（全部只在 gitignore 的 `.work/` 内做副本，不回写仓库文件）：

```powershell
$py = "C:\Users\eie04\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $py tests/engineering/T02/check_gitleaks_allowlists.py --with-controls --gitleaks .tools/t02/gitleaks/gitleaks.exe
```

**已删除的 3 条 `paths` 豁免**改为只按值：SRS 示例 UUID `397c4e7a-…`、T04 已删除测试对象 `55565d49-…`、r01 清单的 6 个 SHA-256。新增第 4 条只按值例外，抑制历史证据里 `docs/api/openapi.yaml`（`e285471760a5dce4…`）与 `docs/api/diff-pages-v1.1.openapi.yaml`（`0db04ea086c2c563…`）两个冻结契约文件摘要，以及 T03-round5 叙述行里的 16 位前缀形态。**没有使用「首尾定长 + 中间通配」**：该写法会把摘要中段变成通配，实测中段改一位仍被抑制，等于又一层全吞；现改为完整字面量；配置自身 0 命中（`regexes` 行不含 key/token 类关键词，故不触规则；实测须把配置复制成中性文件名再扫，因为 gitleaks 会跳过名字恰为 `gitleaks.toml` 的输入：交付配置副本 2,076 字节 / 0 命中，HEAD 配置副本 1,327 字节 / 2 命中，正是 `Idempotency-Key: …` 与 `key=…` 两行），11 个豁免值逐个改首/中/末一位共 33 项全部重新被报。全仓在**不加任何 allowlist** 下实测 15 条 `generic-api-key`（其中 8 条此前被 `paths` 藏起来不可见），逐条账目见 [T02-Revision-R02.md](T02-Revision-R02.md) 3.6 节。

**根因**在生成器：`revision_integrity.py` 原先输出 `{路径: 摘要}`，`json.dumps(indent=2)` 使二者同行，路径含 `secret`/`password` 即触发 `generic-api-key`，每份新清单都要加一条豁免。现由 `digest_records.py` 统一输出 `{"path": …}\n{"sha256": …}` 分行记录，并在序列化后拒绝任何「关键词与 32+ 位十六进制同行」的输出；`integration.py` 的 `artifacts` 同步改为同一记录格式。新生成的清单在**完全不加 allowlist** 的默认规则下实测 0 命中（271 条指纹、47,792 字节，退出 0），不再依赖任何例外。历史证据（含 `evidence/r01-integrity.json`）是不改写记录：生成器现在拒绝写入该冻结路径，默认输出改为 `evidence/r02-integrity.json`（本轮未生成，避免新增未复审证据；命令为 `$py tests/engineering/T02/revision_integrity.py --out <路径>`）。`scan_secrets.py` 新增 `--report`，复跑可把报告指向 `.work` 而不覆盖已跟踪证据。

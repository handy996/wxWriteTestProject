## 3. 数据库迁移现状与权限

- `tests/engineering/T08/migration-draft.sql` 保留为**评审基线**（首行仍标注 DRAFT）；主 agent 已把它的正文安装为 `backend/src/main/resources/db/migration/V5__cost_ledger_pricing.sql`，只替换头 3 行注释。`verify.py` 把这件事做成机器断言：去掉各自头 3 行后正文必须逐字节相等——实测草案为 LF、V5 为 CRLF（12,774B 对 12,947B，173 个 CR 字节），归一化换行后完全相同，因此检查项如实报告两种结果；任何正文偷改都会让该项失败。
- 同一项还断言版本化文件恰为 V1–V5（无第六个）、V5 只创建 `cost_ledger` 与 `cost_pricing_version`、且没有其它版本化文件涉及 cost 表。
- **runner 不再手套草案**：`run_pg.py` 直接按 Flyway 顺序应用 `beforeMigrate__t02_function_defaults.sql` → V1…V5 → `R__t02_function_permissions.sql`、`R__t02_schema_permissions.sql`，与正式迁移路径一致。
- 并发：所有金额上限判定按 scope key 排序获取事务级 advisory lock（ARTICLE / DAY / PROVIDER|MODEL / CLAIM / SLOT），避免跨作用域死锁；结算对 reservationId 单独加锁并用 `status + lock_version` 乐观谓词更新，竞争输者 409，不覆盖赢家。
- 数据库规则：BEFORE-INSERT 上限触发器 `cost_ledger_admit`；BEFORE UPDATE/DELETE 守卫 `cost_ledger_guard`（账本不可删除、事实不可改、预估金额与身份不可变、必须逐 revision 递增、状态机限制）；DEFERRABLE 一致性约束触发器 `cost_ledger_consistent`（RESERVED 不得有事实、UNKNOWN 必须有未解决事实且无终态事实、终态恰好一个终态事实且头行镜像与该事实金额一致；对账后保留的 UNKNOWN 事实不参与终态镜像比较，这是本地集群实跑出来的必要修正）。
- 权限：默认不授权。显式 `GRANT SELECT,INSERT,UPDATE ON editorial.cost_ledger`、`GRANT SELECT ON editorial.cost_pricing_version` 给 `editorial_runtime`，无 DELETE/TRUNCATE、无价格写权限；三个触发器函数 `REVOKE ALL FROM PUBLIC`。V5 应用后的实测授权：`editorial_runtime = INSERT/SELECT/SELECT/UPDATE`（对 cost 两表）加 `audit_log` 的 SELECT/INSERT，`editorial_migrator` 保留 owner 全权限。

## 6. 需要审核的设计取舍

1. `PRICING_NOT_PUBLISHED`=503（配置缺口）与 `PRICING_UNKNOWN`/`GENERATION_PRICE_UNKNOWN`=409（价格未知、自动生图必须拒绝）严格分开；已发布零价可预占。
